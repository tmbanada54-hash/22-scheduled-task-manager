Everything the MVP needs, nothing it doesn't

One clear flow: define a task → the scheduler runs it → every outcome is recorded.

Second-level intervals

Any interval from 5 seconds to a full day, with the next run time computed and displayed for every task.

Retries on failure

A failed execution is retried up to the configured limit, and the attempt count is stored with the run.

Full execution history

Success or failure, timestamp, duration, attempt count and the worker's response — per task, in a modal.

Voice task entry

Tap the mic and say "ping the API every 60 seconds" — the browser's Web Speech API fills the form for you.

Live health metrics

Task counts, runs in the last 24 hours and overall success rate update every time the dashboard polls.

Pause, resume, run now

Stop a task without deleting its config, resume it later, or trigger one execution on demand for a demo.

Three steps from idea to first run

The whole flow fits in a live demo under two minutes.

  1. 01

    Describe the task

    Name it (type or speak), pick an interval, choose Log Message or HTTP Ping, and paste the payload.

  2. 02

    Scheduler takes over

    The backend loop wakes up, claims due tasks, executes the action and writes the result to the store.

  3. 03

    Watch it run

    The dashboard polls every 5 seconds, so counts, next-run timers and history stay current on screen.
